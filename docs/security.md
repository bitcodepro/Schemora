# Local security

Kestrel listens only on 127.0.0.1 and does not use environment/config URL bindings. Every API call requires the current launch's random 256-bit token in X-Schemora-Token. The fragment launch token is removed from the URL and kept in sessionStorage; runtime IDs are not stored there. The exact Host, the Origin when present, and Sec-Fetch-Site are checked. There is no CORS/cookie auth. CSP forbids foreign scripts/connect/embedding; Monaco and workers are bundled locally.

No AI/cloud/telemetry and no connections to production/staging. The application does not execute generated SQL against business databases. Request bodies, clipboard, runtime IDs, SQL output and the JSON parameter payload are neither logged nor stored. The only exception is value sets that the user explicitly saves under a name: they live in `value-sets/<recipe>.dat` in the data directory, encrypted with Windows DPAPI (CurrentUser) with entropy bound to the recipe id, cannot be read under another account or on another computer, and are not part of the catalog, portable export, backups or diagnostics. The set list returns only names and input names; values are read by a separate request on user action. Parse errors return bounded raw snippets only to the current request/UI. An SQL definition that the author explicitly saves is part of the recipe.

Local source paths are checked for absolute/UNC/reparse points. Discovery is read-only and bounded: 250000 entries, 128 depth, 32 MiB/source; static DDL 16 MiB/file / 64 MiB total. ORM configurations are indexed by metadata without reading secrets. Build configuration content hashes do not store the content. An incomplete scan or a roots/excludes race does not replace the previous catalog.

Building requires explicit trust. MSBuild targets/restore run with the user's rights; the stage protects the original files and is not a sandbox for untrusted code. The stage is limited to 20000 files/512 MiB, without links/bin/obj/node_modules/.git. Output/intermediate/packages are redirected into Schemora service directories; a stale bin DACPAC is not used. The verified local closure includes hidden/ignored inputs, sibling projects, ordinary imports, local feeds and resolved pinned DACPAC packages; only input hashes and metadata are stored. Before/after checks block a changed closure. Package code/transitive dependencies, property functions and unsupported custom inputs are diagnosed as incomplete. The arbitrary MSBuild import graph is not executed for planning. Do not trust an unfamiliar project just because a service copy is used.

ProcessRunner uses ArgumentList without a shell, limits output/time and cancels the whole tree; a Windows job closes descendants, and inherited stdout/stderr cannot bypass the timeout. A single writer host holds a lock on the data dir. Recipe saves/approval/render check the version, immutable snapshots and the relationship-context revision under a write gate, preventing a stale preview from being applied and concurrent edits/rejects from being lost.

DACPAC import is limited to 128 MiB and does not execute scripts. DacFx/ScriptDom/Roslyn run in-process with input limits; this is not absolute isolation against specially crafted resource-heavy packages. User C# is never compiled into an assembly or executed; generators/MSBuildWorkspace loading are not run. Dapper parameter objects/values are not read.

The Docker route requires a separate opt-in and a schema-only ZIP with whitelisted metadata entries, expanded bounds and a ban on pre/post/data/payload. Only GUID-named owned resources with ownership labels are created: a container with --network none, no host mounts/ports, a random password, 3 GiB/2 CPU/pids limits. DacFx prepares schema-only DDL offline; docker exec/sqlcmd deploys it and reads the sys catalog. Runtime credentials are passed via the environment, not via password argv, and are not logged. The application does not need an external SqlPackage for this route. After extraction, removal checks owner+exact identity and proves that none of its own resources remain. Cancellation/shutdown trigger cleanup; crash markers allow bounded cleanup at the next start. A failed ownership check keeps the marker/diagnostic and does not remove other people's resources.

SQLite WAL/catalog schema 2. Migration and manual restore create a previous backup; the backup uses the SQLite Backup API rather than copying the live WAL. Restore is allowed from the CLI before the host starts, under the instance lock; a corrupted/future backup is rejected. The backup and the portable manifest are created on explicit action. The manifest exports root names, metadata and recipe definitions; runtime IDs and absolute roots are not included. On import, databases are mapped explicitly.

HTTP request bound 64 MiB, ID processor 8 Mi characters/100000 values, template 512 KiB at the Host, output 64 MiB, stored UI setting 256 KiB. Invalid values block SQL without a silent drop. VARCHAR encoding/collation are checked; types and escaping are tested by actual execution in an isolated SQL Server.



Auto-refresh is off by default, grants no trust and never triggers Rebuild. Manual relations after drift do not gain trust from an earlier manual override; deleting a manual assertion removes only the confirmation tied to it. The build input manifest contains local absolute paths and is not a portable export. Object SQL definitions are stored source metadata; runtime Dapper parameter values are not included.



Language preference contains only en/ru/uk; translation does not persist runtime values. Launch JSON changes only the port on 127.0.0.1, preserves token/Host/Origin checks and rejects unsupported properties. Occupied fixed ports fail explicitly.
